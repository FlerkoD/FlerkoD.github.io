# QUERY CLASH — тренажёр SQL

Браузерная игра для изучения SQL: дуэль карт-операторов, сборка запроса из блоков
и набор запросов на время. 8 учебных баз данных, 3 уровня сложности,
русский и английский языки.

---

## Что нужно установить

**Node.js 20 или новее** — https://nodejs.org (берите версию LTS).

Проверьте, что всё встало:

```bash
node -v    # должно быть v20.x или выше
npm -v
```

База данных **не нужна**, если вы не планируете онлайн-режим (см. таблицу ниже).

| Режим игры | Нужен сервер и база? |
|---|---|
| Дуэль операторов — один против автомата | нет |
| Дуэль операторов — вдвоём за одним экраном | нет |
| Конструктор запросов | нет |
| Скоростной запрос | нет |
| Дуэль операторов — **онлайн по коду комнаты** | **да** |

Рекорды хранятся в браузере (localStorage), задания зашиты в код — поэтому
всё, кроме онлайна, работает на статическом хостинге вроде GitHub Pages.

## 1. Запуск на своём компьютере

```bash
# 1. скачать проект
git clone https://github.com/<ваш-логин>/<ваш-репозиторий>.git
cd <ваш-репозиторий>

# 2. поставить зависимости (один раз, ~1–2 минуты)
npm install

# 3. отключить онлайн-режим, чтобы база не требовалась
echo "NEXT_PUBLIC_ONLINE=0" > .env.local

# 4. запустить
npm run dev
```

Откройте **http://localhost:3000** — игра работает.

Остановить сервер: `Ctrl + C` в терминале.

> Шаг 3 не обязателен, но без него в меню останется кнопка «ОНЛАЙН»,
> которая без базы данных выдаст ошибку сети.

### Проверка «боевой» сборки локально

```bash
npm run build
npm start
```

## 2. Публикация на GitHub Pages (без базы данных)

> В репозитории `FlerkoD.github.io` это приложение находится в подпапке.
> Для публикации вместе с основным сайтом используется workflow
> `../.github/workflows/deploy.yml` из корня репозитория. После успешного
> запуска тренажёр будет доступен по адресу
> `https://flerkod.github.io/interactive-sql-card-game/`.

### Шаг 1. Залить код на GitHub

```bash
git init
git add .
git commit -m "Query Clash"
git branch -M main
git remote add origin https://github.com/<ваш-логин>/<ваш-репозиторий>.git
git push -u origin main
```

Файл `.env` в репозиторий не попадёт — он уже в `.gitignore`.

### Шаг 2. Включить Pages

В репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**.

### Шаг 3. Готово

В репозитории уже лежит `.github/workflows/deploy.yml`. После каждого `git push`
в ветку `main` сайт пересобирается и публикуется автоматически.

Адрес сайта: `https://<ваш-логин>.github.io/<ваш-репозиторий>/`
Прогресс сборки виден во вкладке **Actions**.

> **Если репозиторий называется `<ваш-логин>.github.io`**, сайт лежит в корне домена.
> Откройте `.github/workflows/deploy.yml` и замените
> `BASE_PATH: /${{ github.event.repository.name }}` на `BASE_PATH: ""`.

### Собрать статику вручную

```bash
# для адреса https://<логин>.github.io/<репозиторий>/
BASE_PATH=/<репозиторий> node scripts/build-static.mjs

# для корня домена
node scripts/build-static.mjs
```

Результат — папка `out/` с обычными HTML, CSS и JS. Её можно залить куда угодно:
GitHub Pages, Netlify, Vercel, обычный хостинг.

Проверить локально:

```bash
npx serve out
```

## 3. Полная версия с онлайн-режимом (нужен PostgreSQL)

Онлайн-режим требует настоящего сервера, поэтому **GitHub Pages для него не подойдёт** —
там раздаются только статические файлы. Подойдёт Vercel, Railway, Render или свой VPS.

```bash
# 1. поднять PostgreSQL, например в Docker
docker run --name qc-db -e POSTGRES_PASSWORD=postgres \
  -e POSTGRES_DB=app_db -p 5432:5432 -d postgres:16

# 2. прописать подключение
cp .env.example .env     # внутри уже нужный DATABASE_URL

# 3. создать таблицы комнат
npx drizzle-kit push

# 4. запустить
npm run dev
```

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `DATABASE_URL is required` | Запущен онлайн-режим без базы. Создайте `.env.local` со строкой `NEXT_PUBLIC_ONLINE=0`. |
| На GitHub Pages белый экран, в консоли 404 на `_next/...` | Неверный `BASE_PATH`. Он должен совпадать с именем репозитория и начинаться со слэша. |
| На GitHub Pages нет стилей | Нет файла `.nojekyll` в `out/`. Скрипт `build-static.mjs` создаёт его сам — пересоберите им. |
| `npm ci` падает в Actions | В репозиторий не залит `package-lock.json`. Закоммитьте его. |
| Порт 3000 занят | `npm run dev -- -p 3001` |

## Структура проекта

```
src/
  app/            страница, стили, серверные маршруты (/api/room — только онлайн)
  components/     экраны: меню, три режима игры, руководство, итоги
  content/        базы данных и задания (63 вопроса + 48 запросов)
  game/           правила, подсчёт очков, частицы, звук, сверка SQL
  i18n/            переводы: en.ts и ru.ts
scripts/
  build-static.mjs  статическая сборка для GitHub Pages
```

### Как добавить задание

Откройте `src/content/queries.ts` (целые запросы) или `src/content/duel.ts`
(запросы с пропусками) и допишите строку по образцу соседних — у каждой есть
английский и русский текст.

### Как добавить язык

1. Скопируйте `src/i18n/ru.ts` в `src/i18n/<код>.ts` и переведите значения.
2. Добавьте язык в списки `LOCALES` и `DICTS` в `src/i18n/index.tsx`.

TypeScript сам подскажет, если какой-то ключ забыт.
